Standard library / Threading

Threading and synchronization

SpecifiedUBE 1.0Limited native profile

The threading library identifies workers, waits for completion, requests cooperative stopping, and coordinates shared work.

The declarations below describe the full language contract. The archived implementation provided a bounded set of fresh-status Try thread operations. Those historical APIs are not currently implemented in the restarted compiler. The declarations here describe the full specified library. The admitted native worker profile and bounded concurrent compiler gate have passed; this does not qualify every coordination API listed below.

Current compiler profile

Native source workers are qualified for the admitted scalar and finite record/array profile, including ordinary ByVal copies and ByRef lifetimes. The examples on this page describe the full specified language. The current low-level library uses ThreadPrimitives.Wait(Id, TimeoutMilliseconds) with a required timeout. The global ThreadWait wrapper with an optional timeout, and the broader coordination library, are not qualified by those native worker tests.

Thread operations

Function CurrentThreadId() As LongLong
Function ThreadIsAlive(ByVal Id As LongLong) As Boolean
Function ThreadWait(ByVal Id As LongLong, _
                    Optional ByVal TimeoutMilliseconds As LongLong = -1) As Long
Function ThreadRequestStop(ByVal Id As LongLong) As Long
Function ThreadStopRequested() As Boolean
Sub ThreadYield()

Thread identifiers are nonnegative LongLong program identities. Zero is invalid. They are not operating-system IDs or handles and are not reused during a process.

Waiting and errors

A timeout is in milliseconds. -1 waits indefinitely and 0 polls. Other negative values are invalid. A wait returns 1 when the worker completed successfully. Timeout or cancellation returns 0. These successful results preserve Err. If a fresh FAIL escaped the worker's entry procedure, that worker ends normally and the wait instead reports a fresh FAIL with the worker's captured error number in the waiting thread's Err. No usable wait result is returned. Repeated waits and multiple waiters receive that same outcome, with a fresh FAIL each time. Observing completion makes the worker's preceding actions visible whether it succeeded or failed. Waiting on the current thread or using an identifier that was never issued records Err and reports FAIL, with no usable wait result. The containing statement is skipped by default or transfers to its enabled handler.

Cooperative stopping

ThreadRequestStop records a sticky request and wakes supported waits. The target checks ThreadStopRequested() and returns normally. A completed thread is not an error. UBE never forcibly tears down a running thread.

Thread events

Function CreateThreadEvent(Optional ByVal ManualReset As Boolean = False, _
                           Optional ByVal InitiallySignaled As Boolean = False) _
                           As ThreadEvent

Wait(timeout) returns 1 when signaled and 0 on timeout. An auto-reset event releases at most one waiter for each signal. A manual-reset event releases waiters until Reset. Set and Reset return 1 on success.

Semaphores

Function CreateSemaphore(ByVal InitialCount As LongLong, _
                         ByVal MaximumCount As LongLong) As Semaphore

Wait(timeout) consumes one permit. Release(Optional Count = 1) adds permits and returns 1. An invalid count or overflow records Err and reports FAIL; it is not a successful zero result.

Message queues

MessageQueue.Enqueue(ByVal Value As Variant) copies a value into a FIFO queue. Object payloads retain the same shared reference. Dequeue(ByRef Value As Variant, timeout) returns 1 and writes the destination only when a message is received. Timeout or cancellation leaves the destination unchanged.

Error boundaries

Timeout and cancellation preserve earlier Err information. They are normal status outcomes, not FAIL. Only a fresh FAIL escaping the worker's entry procedure marks completion as failed. Normal return with stale Err is successful; a fresh FAIL with error number zero is still failed. A worker never runs another thread's handler remotely. The caller handles a failed ThreadWait using its own statement and handler rules. User-owned resources still need explicit cleanup before raising. Synchronous UI dispatch, callbacks and orderly shutdown retain separate open delivery contracts. Native source worker qualification is limited to the current admitted compiler profile.

Atomic values

AtomicBoolean, AtomicLong, AtomicLongLong, and AtomicObject provide sequentially consistent operations for one value. Applicable operations include Load, Store, Exchange, CompareExchange, Increment, Decrement, and numeric Add. Use SyncLock when several values must change as one protected operation.

Example

Sub Worker()
    While Not ThreadStopRequested()
        ThreadYield
    Wend
End Sub

Sub Main()
    Dim Id As LongLong
    Id = CallNew Worker()
    Call ThreadRequestStop(Id)
    Call ThreadWait(Id)
End Sub
