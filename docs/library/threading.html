UBE language help / Threading and synchronization

Threading and synchronization

Specified

The threading library identifies workers, waits for completion, requests cooperative stopping, and coordinates shared work.

The functions and types on this page are not yet implemented. Use ThreadPrimitives for the supported worker operations.

Details

Available worker operations

Use ThreadPrimitives to start working with threads today. Its Wait(Id, TimeoutMilliseconds) requires a timeout argument. The convenience functions and synchronization types below are not yet implemented.

Thread operations

Function CurrentThreadId() As LongLong
Function ThreadIsAlive(ByVal Id As LongLong) As Boolean
Function ThreadWait(ByVal Id As LongLong, _
                    Optional ByVal TimeoutMilliseconds As LongLong = -1) As Long
Function ThreadRequestStop(ByVal Id As LongLong) As Long
Function ThreadStopRequested() As Boolean
Sub ThreadYield()

Thread identifiers are nonnegative LongLong program identities. Zero is invalid. They are not operating-system IDs or handles and are not reused during a process.

Waiting and errors

A timeout is in milliseconds. -1 waits indefinitely and 0 polls. Other negative values are invalid. A wait returns 1 when the worker completed successfully. Timeout or cancellation returns 0. These successful results preserve Err. If the worker ends with an unhandled error, the wait fails with that error number in the waiting thread’s Err instead of returning a value. Repeated waits and multiple waiters receive that same outcome, with a new failure each time. Observing completion makes the worker's preceding actions visible whether it succeeded or failed. Waiting on the current thread or using an identifier that was never issued records Err and fails, with no usable wait result. The containing statement is skipped by default or transfers to its enabled handler.

Cooperative stopping

ThreadRequestStop records a stop request that remains set and wakes supported waits. The target checks ThreadStopRequested() and returns normally. A completed thread is not an error. UBE never forcibly tears down a running thread.

Thread events

Function CreateThreadEvent(Optional ByVal ManualReset As Boolean = False, _
                           Optional ByVal InitiallySignaled As Boolean = False) _
                           As ThreadEvent

Wait(timeout) returns 1 when signaled and 0 on timeout. An auto-reset event releases at most one waiter for each signal. A manual-reset event releases waiters until Reset. Set and Reset return 1 on success.

Semaphores

Function CreateSemaphore(ByVal InitialCount As LongLong, _
                         ByVal MaximumCount As LongLong) As Semaphore

Wait(timeout) consumes one permit. Release(Optional Count = 1) adds permits and returns 1. An invalid count or overflow records Err and fails; it is not a successful zero result.

Message queues

MessageQueue.Enqueue(ByVal Value As Variant) copies a value into a FIFO queue. An object value still refers to the same object. Dequeue(ByRef Value As Variant, timeout) returns 1 and writes the destination only when a message is received. Timeout or cancellation leaves the destination unchanged.

Error boundaries

Timeout and cancellation preserve earlier Err information. They are normal status outcomes, not failures. Only a new failure escaping the worker's entry procedure marks completion as failed. Normal return with an earlier Err value is successful; a new failure with error number zero is still failed. A worker never runs another thread's handler remotely. The caller handles a failed ThreadWait using its own statement and handler rules. User-owned resources still need explicit cleanup before raising.

Atomic values

AtomicBoolean, AtomicLong, AtomicLongLong, and AtomicObject provide sequentially consistent operations for one value. Applicable operations include Load, Store, Exchange, CompareExchange, Increment, Decrement, and numeric Add. Use SyncLock when several values must change as one protected operation.
