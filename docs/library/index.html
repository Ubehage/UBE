Standard library

Partially implementedFresh UBECore sourceNo released library binary

UBECore supplies reusable operations for ordinary UBE programs. Its procedures are declared in library source rather than made part of the language grammar.

Current UBECore is the fresh std-lib/ project. The previous source library is archived; its APIs and preview results do not establish current availability. Bounded source qualification through bootstrap tools does not mean the fresh compiler can execute your program.

Current source reference

  • ByteBuffer: owned bytes, geometric growth and independent snapshots.
  • UTF-8 and Unicode scalars: decoding, validation, letter classification and simple folding.
  • Counted-byte files and paths: file input, arguments, explicit close, lexical resolution and identity.
  • Fresh-status thread operations: identity, liveness, wait, cooperative stop and yield.
  • Scalar and byte-key utilities: current source contracts with separate qualification obligations.

Owned byte buffers

A zero-initialized ByteBuffer is empty. Append arbitrary bytes, including zero, and publish independent snapshots. Capacity and logical length are separate. The reference describes failure preservation, alias restrictions and caller synchronization.

Incremental UTF-8 decoding

Feed one byte at a time and use the fresh Complete flag to distinguish a completed scalar from partial input. Finish detects truncation; Reset starts another stream. See UTF-8 and Unicode scalars.

Unicode scalar helpers

Current helpers provide versioned letter classification, simple folding and immutable byte-span decoding. They do not normalize text or replace builtin String. Their declarations and ownership rules are on the Unicode reference page.

Counted file bytes and arguments

File tokens own external resources and must be closed explicitly, including after failed cleanup. Paths and arguments use strict counted UTF-8. See files and paths for fresh status, retries and current Windows limits.

Specified UBE 1.0 support

The full language contract also defines scalar conversions, Variant inspection, automatic managed memory, ordinary thread functions, atomic values, thread events, semaphores and message queues. These references describe specified behavior; they are not a claim that the fresh implementation supplies the full catalog:

  • Conversions
  • Variant inspection
  • Managed memory and CollectGarbage
  • Threading and synchronization

UBE's native outputs are intended to contain the program-support code they need without a separately installed UBE runtime or virtual machine. Current source tests do not establish a released compiler or library package.

Resources and errors

Managed memory does not close files, sockets or handles opened by your code. Release them on success, failure and cancellation. A successful operation does not clear an old Err. When an API returns fresh Boolean status, use that result and its documented outputs to decide whether this call succeeded.

Remaining catalog

The full public API and individual API A-Z entries remain incomplete. General strings, conversions, collections, console I/O, dates, mathematics, full synchronization, events, processes and networking need their complete declarations and matching evidence. Undefined names, signatures and release commands are not promised by this overview.
