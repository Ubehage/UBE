Fresh-status thread operations

Partially implementedCurrent UBECore source - bounded Windows bootstrap

These operations report whether a thread request succeeded separately from the value it returned. They work with existing UBE thread identities and cooperative stopping.

Declarations

Function TryCurrentThreadId(ByRef Id As LongLong) As Boolean
Function TryThreadIsAlive(ByVal Id As LongLong, ByRef Alive As Boolean) As Boolean
Function TryThreadRequestStop(ByVal Id As LongLong, ByRef Requested As Boolean) As Boolean
Function TryThreadStopRequested(ByRef Requested As Boolean) As Boolean
Function TryThreadWait(ByVal Id As LongLong, ByVal Timeout As LongLong, ByRef Completed As Boolean) As Boolean
Function TryThreadYield() As Boolean

These explicit Try contracts return an ordinary Boolean status and may record Err without raising a language failure. This record-only behavior is distinct from Err.Raise/FAIL; it must not be inferred for other APIs merely from a Try prefix. The removed implementation's historical qualification is not evidence of support in the restarted compiler.

Return values and errors

True means the request was processed and any output is fresh. It preserves incoming Err. False preserves the old output and records a new error occurrence. An earlier error number, including the same number as a later error, is not a success test.

Identities are positive LongLong program values, never operating-system handles or pointers. Zero and unknown identities fail. A completed issued worker can still be queried: a successful liveness query returns Alive = False; a successful stop request can return Requested = False because the worker already completed.

Waiting and ownership

Timeout is milliseconds from 0 through 4,294,967,295, or -1 for indefinite waiting. Self-wait and other values fail. A successful request with Completed = False means timeout or interruption. It does not mean the worker finished. Only True with Completed = True permits completion cleanup and provides visibility of the worker's preceding actions.

Example

This specified caller fragment assumes WorkerId is an issued worker identity. It has not been executed as a manual example with the fresh compiler.

Dim Completed As Boolean = False
If TryThreadWait(WorkerId, -1, Completed) Then
    If Completed Then
        ' Worker is finished; its retained inputs may now be released.
    End If
Else
    ' Handle the failed request; keep the worker's state alive.
End If

Thread safety and availability

Stop requests are sticky and cooperative. Stop admitting work, request stopping where appropriate, then drain workers before releasing shared inputs. These calls borrow output storage for the call and retain no source or compiler state. Callers synchronize shared mutable outputs.

The bounded source implementations and native/UBE thread tests are recorded in the current UBECore evidence. No released standalone library binary is available. This API is not the complete specified threading and synchronization library, and does not provide an executor or choose a worker budget.
