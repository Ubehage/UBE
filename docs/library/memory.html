UBE language help / Managed memory and collection

Managed memory and collection

Partially implemented

UBE automatically frees storage for Strings, arrays and records that your program can no longer use. Call Memory.CollectGarbage to request collection immediately.

Details

Memory declarations

Public Intrinsic Function CollectGarbage() As Long

Return value

Returns 1 if the call freed unused managed storage, or 0 if it freed none. The result depends on which values your program can still use at the time of the call.

Lifetime

Values remain available while your program uses them, including values in array elements, record fields and worker arguments. UBE also collects automatically when more storage is needed. You do not free a String manually.

Objects, recursive custom types and class termination are not yet implemented.

Resources and concurrency

Collection does not close files, native handles, sockets or other user-owned resources. Close those explicitly on success and failure paths. Collection accounts for managed values across UBE threads but does not synchronize your shared application state.

Example

Public Function Main() As Long
    Main = Memory.CollectGarbage()
End Function

Expected result

The program returns 0 or 1 according to whether this collection reclaimed storage. No specific amount of reclaimed memory is promised.
