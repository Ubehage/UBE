Counted-byte files and paths

Partially implementedCurrent UBECore source - bounded Windows bootstrap

Read uninterpreted file bytes and resolve strict UTF-8 paths without using zero-terminated source text. File tokens have explicit ownership and must be closed.

File and argument declarations

Function TryOpenByteFile(ByRef PathUtf8() As Byte, ByVal MaximumBytes As Long, ByRef Token As Long, ByRef Length As Long, ByRef Failure As Long) As Boolean
Function TryReadByteFile(ByVal Token As Long, ByRef Destination() As Byte, ByVal Start As Long, ByVal Count As Long, ByRef ReadCount As Long, ByRef Failure As Long) As Boolean
Function TryCloseByteFile(ByRef Token As Long, ByRef Failure As Long) As Boolean
Function TryCommandArgument(ByVal Index As Long, ByRef Result() As Byte, ByRef Failure As Long) As Boolean

Start with Token = 0. Open checks file size against MaximumBytes before allocating read scratch storage. Read borrows destination storage and accepts at most 65,536 bytes per call. Start is a zero-based payload offset, independent of the array's language lower bound. A positive short read is progress; zero bytes means EOF. Failure preserves destination bytes and returns ReadCount = 0.

Command arguments exclude the executable, use zero-based indexes and publish independent arrays only on success. File contents remain uninterpreted bytes. Paths are strict UTF-8 without embedded NUL.

Close explicitly

Copying a token does not duplicate its resource. Close after success, failure and cancellation. Closing zero succeeds. If close genuinely fails, the token remains owned for retry. Failed opening cleanup can also return an owned nonzero token despite False; check and close it. Neither garbage collection nor leaving scope closes the file.

Path declarations

Function TryCurrentDirectoryBytes(ByRef Published() As Byte, ByRef Failure As Long) As Boolean
Function TryNormalizeRelativePathBytes(ByRef Path() As Byte, ByRef Published() As Byte, ByRef LeadingParents As Long, ByRef Failure As Long) As Boolean
Function TryResolvePathBytes(ByRef BaseDirectory() As Byte, ByRef Path() As Byte, ByRef Published() As Byte, ByRef Failure As Long) As Boolean
Function TryReadByteFileIdentity(ByVal Token As Long, ByRef Published() As Byte, ByRef Failure As Long) As Boolean

Capture the working directory once; later resolution uses that captured absolute base. Normalization is lexical and performs no file access: it accepts relative paths, removes redundant separators and ., cancels component/.. pairs, and retains/counts remaining leading parents. For example, src/../Main.bas becomes Main.bas; ../shared/./Main.bas becomes ../shared/Main.bas with one leading parent.

Resolve combines a relative path with an absolute base or normalizes an already absolute path. Current roots are drive roots such as C:/ and UNC roots such as //server/share/. Parent components cannot remove the root. Drive-relative paths and device namespaces are unsupported. The maintained Windows implementation reads both separators and writes /. It preserves spelling without environment expansion, case folding or Unicode normalization.

Identity borrows an existing open token, opens no additional handle and publishes 16 opaque bytes. Compare the complete result within the request; do not persist, decode or use it as an address. The caller still owns the token on success or failure. Lexical normalization does not establish physical containment across links, and identity is not a filesystem snapshot.

Status, errors and lifetime

Use the fresh Boolean and Failure, not stale Err. Success preserves incoming Err. Path callers seed Failure = 8 and, where present, LeadingParents = 0 before managed entry. Path failure preserves old published arrays and resets LeadingParents to zero. Results are independent arrays; input references are borrowed only for the call. Keep output variables distinct from inputs and other outputs.

Paths are limited to 131,068 UTF-8 bytes and 32,767 UTF-16 code units on the maintained host. Independent calls may share immutable bytes; synchronize mutable arrays and follow token busy rules. The source APIs have bounded Windows qualification; other platforms and a released library binary remain unavailable.
