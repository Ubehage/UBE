Files and paths

Implemented

Open files, read and write bytes, then close each file when you finish.

Parameters

PathUtf8, SourceUtf8 and DestinationUtf8 contain complete path bytes. Token identifies an open resource. Start is a zero-based byte offset and Count is the requested byte count. ReadCount and WrittenCount report actual bytes transferred. Length is a byte length; MaximumBytes limits accepted file size. Failure receives zero on success or an operation failure code.

Opening and ownership

Paths are counted strict UTF-8 bytes, not zero-terminated text. TryOpen opens a read-only regular file within MaximumBytes and returns Token and Length. Token must initially be zero. TryCreateNew creates a writable file exclusively; an existing path is never truncated by that operation. A token identifies an open file, not a memory address. Copying the number does not open another file; close each open file only once.

TryClose sets Token to zero after a successful close. A failed close retains the live token so the caller can retry. Every caller remains responsible for cleanup. TryOpenDirectory opens a directory for reading its information; it does not enumerate contents.

Transfers

TryRead and TryWrite transfer bounded chunks and report actual progress. The destination array changes only after a successful read. Writes may partially change a file before reporting failure. TryFlush does not close its token.

TryReadAllBytes reads at most the smaller of MaximumBytes and 1,048,576, detects premature EOF or growth, closes the file before setting Result, and leaves an existing Result unchanged on failure. If closing fails, Token still identifies the open file so you can retry. TryReadOpenBytes uses an already-open token, reads bytes from its current position, checks for the end of the file and leaves the file open.

TryWriteByteRange checks the requested byte range and writes it in chunks of at most 65,536 bytes, retrying any unwritten remainder. It neither flushes nor closes. TryWriteAllBytes writes the entire array and flushes after success; the caller must still close. Zero progress is a failure, not an infinite retry.

TryReadOpenBytes requires Length from 0 through 1,048,576 bytes. A negative or larger length returns False with Failure 1 and Err 5, leaving Result unchanged.

File information and replacement

TryFinalPath returns the actual path of the open file or directory. TryIdentity returns 12 bytes identifying the file; compare these bytes to test file identity, not as a path or memory address. TryLength does not change file position. TryDelete deletes one named file. TryReplace replaces a destination by a same-volume move; it does not silently copy across volumes.

Errors

These Try operations return ordinary Boolean status and an explicit Failure value. Successful calls preserve Err. Check the returned status rather than an older Err.Number. Invalid write spans record Failure 1 and Err 5; stalled progress records Failure 15 and Err 57. SetError records a recoverable error and returns False without raising. TryClosePreservingError attempts cleanup while preserving the error from an earlier failed operation.

Use separate variables for outputs. Do not read or write through the same token from multiple threads at once. These file operations currently support Windows x64. Observe each operation’s size and path limits.
