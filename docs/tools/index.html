Compiler and tools

Partially implementedCompiler v2 availableUBE 1.0 compiler v3 specified

Compiler v2 is the self-hosting transition compiler. Compiler v3 is the first public-release target and will implement the UBE 1.0 language definition.

Current development build

From the repository root on the supported Windows development setup, run:

./bootstrap/build.ps1

This command builds and tests the bootstrap chain and preserved compiler generations. It is a contributor command, not the final public compiler interface.

Native source files

A native file starts with a versioned header whose kind matches its extension:

UBE SOURCE 1 MODULE
Attribute UBE_Name = "Main"

Public Sub Main()
End Sub
ExtensionKind
.basMODULE
.clsCLASS
.frmFORM
.ctlCONTROL

Project manifest

A normal UBE 1.0 build consumes a UTF-8 .UBE project manifest:

UBE-Project 1
Name = "Greeting"
Kind = "Exe"
Startup = "Main"
Source = "src/Main.bas"
Source = "src/Messages.bas"

Source order is significant. Paths are relative to the manifest and may not escape the project directory. Kind = "Library" builds a native shared library and exposes only module procedures marked Public Export.

Other build inputs

  • .UBG lists projects to build in order. It is orchestration input, not one combined link unit.
  • .UBR stores binary resources separately from textual source and manifests. Its byte layout is not yet frozen.

Diagnostics and safety

Malformed source, manifests, paths, and resources must produce a controlled diagnostic. They must not crash the compiler. See UBE1001: source contains a NUL byte for the current diagnostic-page format.

Not yet public

The final command-line options, optimization settings, debug controls, target selection, and cross-compilation interface are not frozen. The native debugger and IDE are planned.
