Compiler and tools

Partially implementedFresh v3 checking subsetNo program generation yet

The fresh Compiler v3 is the active implementation and first public-release target. It currently reads source and projects and checks bounded syntax; full semantic checking and program generation remain unfinished.

Current development commands

With the qualified development executable available, run from the repository root:

./bootstrap/out/v3/ube.exe --check path/to/Main.bas
./bootstrap/out/v3/ube.exe --check path/to/App.UBE --jobs 4

Even accepted syntax returns UBE1012 and exit code 1, with no executable. Read Check source and projects for prerequisites, option rules and limits. The historical bootstrap/build.ps1 route selects archived compiler source and does not build fresh v3.

Specified build inputs

The formats below describe the full UBE 1.0 contract. The current checking subset supports fewer facilities, as listed on the command page.

Native source files

A native file starts with a versioned header whose kind matches its extension:

UBE SOURCE 1 MODULE
Attribute UBE_Name = "Main"

Public Sub Main()
End Sub
ExtensionKind
.basMODULE
.clsCLASS
.frmFORM
.ctlCONTROL

Project manifest

A normal UBE 1.0 build consumes a UTF-8 .UBE project manifest:

UBE-Project 1
Name = "Greeting"
Kind = "Exe"
Startup = "Main"
Source = "src/Main.bas"
Source = "src/Messages.bas"

Source order is significant. Paths are relative to the manifest and may not escape the project directory. Kind = "Library" builds a native shared library and exposes only module procedures marked Public Export.

Other build inputs

  • .UBG lists projects to build in order. It is orchestration input, not one combined link unit.
  • .UBR stores binary resources separately from textual source and manifests. Its binary layout is specified; fresh-v3 resource consumption is unfinished.
  • .UBL is the specified compiled-library bundle. See resources and compiled libraries.

Diagnostics and safety

Malformed source, manifests, paths, and resources must produce a controlled diagnostic. They must not crash the compiler. See UBE1001: source contains a NUL byte for a preserved v2 diagnostic, and UBE1012 for the active checker boundary. Codes are scoped to their compiler; this is not a complete fresh-v3 diagnostic catalog.

Not yet public

The final command-line options, optimization settings, debug controls, target selection, and cross-compilation interface are not frozen. The native debugger and IDE are planned.
