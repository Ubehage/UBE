Check source and projects

Partially implementedFresh Compiler v3 - Windows x86-64 development tool

The fresh Compiler v3 reads native source and a bounded project format, then checks supported syntax. It cannot yet validate a complete program or generate an executable.

Prerequisites

Use the repository's qualified development executable at bootstrap/out/v3/ube.exe. This manual does not provide a standalone compiler installation. Contributor build prerequisites and qualification procedures are maintained in bootstrap/README.md and compiler/UBE_Compiler_v3/tools/. The historical bootstrap/build.ps1 route selects archived compiler source; it does not build the fresh v3.

Commands

./bootstrap/out/v3/ube.exe --check path/to/Main.bas
./bootstrap/out/v3/ube.exe --check path/to/App.UBE
./bootstrap/out/v3/ube.exe --check path/to/App.UBE --jobs 4

Run these commands from the repository root in PowerShell. Quote paths containing spaces. Relative invocation paths use the working directory captured at the start of the request. Options use the exact spelling and order shown.

--jobs is available only for project input. The default is one worker. Its value must be ASCII decimal digits with a numeric value from 1 through 4; leading zeroes are accepted. Signs, missing values, repeated options and additional options are usage errors. Worker count does not change which source failure is reported first.

Current project subset

The root manifest must have Kind = "Exe", Startup = "Main", a name and at least one source. It may explicitly reference one direct source library whose manifest name is UBECore and whose kind is Library. No library is found implicitly. Source processing follows root manifest order, then reference manifest order.

Native MODULE source has the qualified parser subset. Full grammar, conditional branch selection, other source kinds and designer input remain incomplete. Other libraries, transitive references, groups, resources, compiled libraries and startup forms are outside this project consumer. A valid unsupported facility is reported as unavailable; that does not make it invalid UBE.

The checker reads project structure and syntax. It does not establish that Main binds correctly, names exist, assignments have compatible types, exports are valid, or referenced library bodies have passed semantic checking. Optimization and DebugInformation values can be retained as metadata without generating code.

Results and exit codes

Exit codeMeaning today
1Rejected, unsupported, cancelled or unfinished checking. Even accepted syntax ends with UBE1012.
2Invalid invocation or command-argument transport failure.
error UBE1012: source checking is not implemented

That message means the syntax step reached the current semantic-checking boundary. It is not a successful build. No output program is created, and exit zero is not currently a successful-check outcome. See UBE1012.

Paths and limits

Source paths must remain within their manifest's lexical directory tree. Relative references may reach a sibling library. Containment is lexical: junctions and symbolic links can reach outside that tree. Opened-file identities detect aliases and duplicates within the qualified policy; the checker does not promise a filesystem snapshot.

Current request ceilings are 1 MiB per manifest, two packages, 256 sources, 16 MiB per source, 64 MiB total source bytes, 4 MiB total declared/resolved path bytes, and 8 MiB retained manifest/path/name bytes. Counted UTF-8 paths are limited to 131,068 bytes and the maintained Windows adapter's UTF-16 bound. These are development resource limits, not language limits.

Diagnostics

Project errors identify the owning input, original one-based line and Unicode-scalar column, and zero-based byte offset. Parallel source failures are selected in canonical source order. A filename is quoted and control characters are escaped. Error codes and exact messages are scoped to the compiler that emitted them; preserved v2 diagnostics are not a fresh-v3 catalog.

Read the complete specified project format separately from this implemented subset.
