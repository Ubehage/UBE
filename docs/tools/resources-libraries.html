Resources and compiled libraries

SpecifiedUBE 1.0 - fresh v3 packaging unavailable

Resource sidecars keep binary assets out of source text. Compiled-library bundles pair native code with explicit target and interface identities.

Resource sidecars (.UBR)

Keep pictures, icons and other binary payloads in a sidecar such as MainWindow.UBR, normally beside the owning form/control source. List every sidecar explicitly in the project:

Resource = "src/MainWindow.UBR"

Designer text refers to a named entry rather than embedding bytes or trusting an unchecked offset. Unreferenced sidecars are not searched or embedded automatically.

Specified container framing

UBE-Resource 1 is little-endian. Its 16-byte header consists of the eight magic bytes UBEUBR1 followed by LF, a 32-bit unsigned entry count and a 32-bit unsigned directory length. Each directory record holds a 16-bit unsigned ASCII name length, a zero 16-bit flags field, 64-bit unsigned payload offset and length, 64 uppercase ASCII hexadecimal SHA-256 characters, and the name bytes. These field widths describe the file format, not additional UBE scalar types.

Names contain 1 through 255 ASCII letters, digits, underscores, hyphens or dots. Records use strict ordinal name order. Payloads immediately follow the directory in that order, with no gaps or trailing bytes. A container is limited to 64 MiB and 1,024 entries. Readers validate lengths, ranges, ordering and hashes before exposing any data; malformed or unsupported input requires a controlled diagnostic.

Compiled-library bundles (.UBL)

UBE-LibraryBundle 1 uses the same framing with magic UBEUBL1 followed by LF. It contains exactly three entries in canonical order:

EntryContents
ArtifactTarget-specific native library
InterfaceCanonical public declaration record
ManifestUTF-8 compatibility and artifact metadata

Metadata includes package name, semantic version, language version, intrinsic ABI, target triple, object format, pointer width, public-interface SHA-256 and artifact SHA-256. A matching bundle format alone does not make two targets or interfaces compatible.

Explicit references and compatibility

Reference = "vendor/TextTools/TextTools.UBE"
LibraryReference = "vendor/TextTools/TextTools.UBL|1.4.0|0123456789ABCDEF0123456789ABCDEF0123456789ABCDEF0123456789ABCDEF"

The specified LibraryReference form requires the path, semantic version and exact uppercase 64-digit interface hash. The selected target must match. The documented paired source-reference form supplies declarations explicitly; no registry, network or library filename supplies missing metadata. The canonical core package name is UBECore. Package, language, source format, compiler and intrinsic ABI versions are separate identities.

Current availability

These formats remain normative definitions preserved from the earlier work. Archived preview evidence does not establish an active packager or linker. The fresh-v3 checker reports Resource, LibraryReference and other packaging facilities as unimplemented; it creates no native artifact. No resource or bundle generation command is promised here.
