Project manifests

Partially implementedUBE 1.0Fresh v3 bounded input subset

A UTF-8 .UBE file defines one executable or library package and its ordered source modules.

Current checking subset

The fresh v3 accepts an Exe root with Startup Main and at most one explicit direct source reference named UBECore. It processes native MODULE syntax with one through four workers. Other library packages, transitive references, groups, resources, compiled libraries and StartupForm are not yet available. The bounded semantic check covers all admitted declarations and bodies in both packages. Wholly supported input can succeed with exit zero; an unused unsupported body still prevents success. The current qualified local CLI is required, and no executable is generated. See current commands and limits.

Specified format example

This full-format example includes StartupForm and another library; those facilities exceed the current input subset.

UBE-Project 1
Name = "Greeting"
Kind = "Exe"
Startup = "Main"
StartupForm = "MainWindow"
Reference = "vendor/TextTools/Library.UBE"
Source = "src/Main.bas"
Source = "src/MainWindow.frm"

Sources and paths

Source entries are processed in manifest order. Paths are relative to the manifest, use portable syntax, and may not escape the package directory. A source header's kind must agree with its extension. Attribute UBE_Name supplies the module or type name.

References

Each Reference names a directly referenced source-library project. Its explicit relative path may use parent segments to reach a sibling library, such as ../TextTools/Library.UBE; each library's Source entries remain within its own directory. Absolute reference paths and undeclared search paths are not accepted. References are ordered for deterministic building, but order never resolves an ambiguous name. Visibility is direct and non-transitive: a package does not automatically see its dependency's dependencies. Use Package.Module.Member when qualification is needed. Friend never crosses a package boundary. The preserved bootstrap has its own bounded library behavior. It does not establish fresh-v3 name resolution or override the direct-UBECore checking limit above.

Startup and shutdown

Dependencies initialize first, followed by this package's modules in source order. If StartupForm is present, that default form loads after module initialization and before Main. Startup = "Main" selects the program entry point. Orderly shutdown terminates modules and dependencies in reverse order.

Resources and compiled libraries

Kind = "Library" permits module-level Public Export procedures. The normative format defines .UBR resources, .UBL compiled-library bundles and LibraryReference = "path.UBL|version|interface-sha256". UBECore is the canonical core package identity. These specified packaging formats are not implemented by fresh v3. See resources and compiled libraries for contents and compatibility requirements.

Build settings

Optimization accepts 0, 1, 2, 3 or Size; its default is 2. DebugInformation accepts None, Line or Full; its default is Full. The current checker retains supported metadata but emits no code or debug information.
