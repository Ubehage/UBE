Project manifests

SpecifiedUBE 1.0Compiler v3 implementation pending

A UTF-8 .UBE file defines one executable or library package and its ordered source modules.

Example

UBE-Project 1
Name = "Greeting"
Kind = "Exe"
Startup = "Main"
StartupForm = "MainWindow"
Reference = "vendor/TextTools/Library.UBE"
Source = "src/Main.bas"
Source = "src/MainWindow.frm"

Sources and paths

Source entries are processed in manifest order. Paths are relative to the manifest, use portable syntax, and may not escape the package directory. A source header's kind must agree with its extension. Attribute UBE_Name supplies the module or type name.

References

Each Reference names a directly referenced source-library project. Its explicit relative path may use parent segments to reach a sibling library, such as ../TextTools/Library.UBE; each library's Source entries remain within its own directory. Absolute reference paths and undeclared search paths are not accepted. References are ordered for deterministic building, but order never resolves an ambiguous name. Visibility is direct and non-transitive: a package does not automatically see its dependency's dependencies. Use Package.Module.Member when qualification is needed. Friend never crosses a package boundary. The bounded bootstrap currently supports independent direct Public-only libraries; full qualification and nested dependencies remain outside that subset.

Startup and shutdown

Dependencies initialize first, followed by this package's modules in source order. If StartupForm is present, that default form loads after module initialization and before Main. Startup = "Main" selects the program entry point. Orderly shutdown terminates modules and dependencies in reverse order.

Libraries and unresolved packaging details

Kind = "Library" permits module-level Public Export procedures. The portable compiled-library container, dependency version compatibility, and canonical core-library package identity are not yet frozen. This page therefore documents source-project references only and does not invent a binary package format.
