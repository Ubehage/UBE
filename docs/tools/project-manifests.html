UBE language help / Project manifests

Project manifests

Partially implemented

A .UBE file lists your program’s modules and build settings.

Details

Executable project

Sources are read in the order listed. The header, Name, Kind and at least one Source are required; an executable also needs Startup = "Main".

UBE-Project 1
Name = "Example"
Kind = "Exe"
Startup = "Main"
Source = "Main.bas"
Source = "Helpers.bas"
Optimization = "2"

Writing entries

Quote values and double any quote within a value. Blank lines and apostrophe comment lines are allowed. Key names ignore case. Repeat Source for each file; other keys appear once. Source paths are relative to the project file and must remain inside its directory tree.

Source files

Each Source entry names a native .bas module or .cls class. The extension must agree with its source header: MODULE for .bas and CLASS for .cls. See Projects, modules, and files for its header. List any required ordinary library modules explicitly.

Empty named classes are available; class members and lifecycle hooks remain unsupported. For a class named Gate, add Source = "Gate.cls" to the project and use this complete Gate.cls file:

UBE SOURCE 1 CLASS
Attribute UBE_Name = "Gate"
Option Explicit

Build settings

Optimization accepts 0, 1, 2, 3 or Size; its default is 2. DebugInformation accepts None, Line or Full, defaulting to Full. Source-level debugging is not yet complete.

Note

Current builds accept executable projects. General library references, resource packaging and startup forms are not yet implemented; see Resources and compiled libraries.
