Resume

SpecifiedFresh v3 execution unavailableError-handling statementReserved wordUBE 1.0

Continues execution from an error handler.

Syntax

Resume [Next | label]

Example

Sub Main()
    On Error GoTo Handler
    Dim Count As Long
    Count = CLng(Command$())
    Exit Sub
Handler:
    Resume Finished
Finished:
    Print "Continued"
End Sub

Expected result

If the runtime command-line text cannot convert to Long, the example enters Handler and prints Continued. At Finished, Err.Number is zero because Resume cleared the recorded error. Valid input exits without printing. These are specified outcomes; compiler execution is not yet verified.

Important rules

Use Resume only from an active error handler. Every valid form clears the recorded Err information as execution resumes. Resume Next continues after the statement that caused the error. In contrast, On Error Resume Next keeps the newly recorded error while continuing after a failure.

Failed-call statement skipping is also the default when no label handler is enabled. A failed call received while the handler is running skips its own statement without recursively entering the handler or replacing the saved resume location. For a failed If/ElseIf or Do/Loop condition, Resume retries that condition and Resume Next continues after the whole construct. Retrying a post-test condition does not repeat the body first. Resume syntax remains outside the current bootstrap subset; boundaries for For, Select Case and SyncLock remain under definition.
