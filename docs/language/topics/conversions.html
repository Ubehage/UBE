Conversions

Partially implementedUBE 1.0Compiler support in progress

UBE performs defined scalar conversions when they are safe to request and rejects unrelated values.

Known values

Dim Caption As String = 42
Dim Count As Long = "123"

The stored values are "42" and 123. If a constant conversion is invalid or outside the destination range, compilation fails.

Runtime values

If validity depends on input, a permitted conversion is checked while the program runs. Failure records the error in that thread's Err and reports FAIL without a usable result. By default the containing statement is abandoned; an unfinished assignment leaves its destination unchanged. An enabled label handler receives control instead. A successful operation does not clear an older error.

Numeric rules

Numeric narrowing is range-checked and never wraps or saturates. Fractional values converted to an integer round to the nearest integer, with an exact half rounded to the even result. Integer, Currency, and Decimal arithmetic is checked. Single and Double admit finite IEEE-754 values only, preserving signed zero and subnormals. NaN and infinities fail. A conversion outside the destination range records error 6; converting to an integer rounds to nearest, ties to even, before checking its integer range.

The Windows x64 development compiler supports conversions among Boolean, Byte, Integer, Long, LongLong, Single, Double and String. The wider rules on this page, including Currency, Decimal, Date and Variant, are specified separately and are not implied by that support.

Text and dates

Default conversion is independent of the computer's locale. Numeric text must be a complete valid number. Single and Double text uses invariant decimal notation; malformed input or NaN/infinity spellings record error 13, and a finite number outside range records error 6. Output uses the fewest significant decimal digits that read back as exactly the same floating value, preserving negative zero as -0. Among those values it chooses the nearest decimal, ties to even, then the shorter fixed or normalized scientific spelling (fixed on a tie). Fractions keep a leading zero; scientific spelling uses uppercase E without a redundant plus sign or exponent zeros. Canonical date text is YYYY-MM-DDTHH:MM:SS[.fraction]. Locale-specific input and display require an explicit library function.

Compatibility built-ins

Specifically documented compatibility built-ins such as Mid$ and Len can accept broad scalar inputs and convert text-consuming arguments using invariant representations. This is their declared call contract; it does not loosen ordinary user-procedure signatures or direct ByRef matching. An object-accepting built-in receives an opaque managed identity token, never a dereferenceable address. The individual API must define its conversion and handle behavior; do not invent a string representation from a host pointer.

Restrictions

Ordinary assignment and user-procedure calls do not implicitly turn objects into scalars. The explicitly documented broad-input built-in boundary above is separate. Date does not implicitly convert to or from a number or Boolean. Null converted to a fixed type fails; Empty converts to that type's neutral value. A Variant keeps the exact type assigned to it.
