Events and program lifetime

SpecifiedUBE 1.0Compiler support in progress

A program remains active while it has a live UBE thread or an active callback-event source.

After Main returns

Worker threads continue running. A loaded form, active timer, listener, file watcher, or similar registered source keeps the process alive and receives messages. A merely allocated object that declares events does not.

Orderly shutdown starts only after the final thread returns and the final event source is unloaded or closed. Module termination then runs in reverse initialization order before final managed cleanup.

Synchronous and recursive events

Events run synchronously unless an API explicitly says otherwise. RaiseEvent returns after its handlers finish. A handler may cause the same event to fire again; this follows ordinary recursion rules.

Form unloading

A form first calls Form_Unload(ByRef Cancel As Integer). A nonzero Cancel leaves it loaded. If accepted, new callbacks are rejected, the window and native handles are released, active procedures drain, and every alias becomes Nothing when unloading completes.

Example

Sub Main()
    Load MainWindow
    MainWindow.Show
End Sub

The loaded window remains an active event source after Main returns. Native user-interface support is not yet released.
