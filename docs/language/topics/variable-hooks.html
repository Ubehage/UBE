Variable access hooks

SpecifiedUBE 1.0 - fresh v3 execution unavailable

Attach procedures to reads and writes of a stored variable while callers keep ordinary variable syntax. The variable still owns real backing storage.

Syntax

Private Temperature As Double
    On Get TemperatureRead
    On Set TemperatureWritten
End Variable

Private Function TemperatureRead(ByRef Storage As Double) As Double
    TemperatureRead = Storage
End Function

Private Sub TemperatureWritten(ByRef Storage As Double, ByVal Value As Double)
    Storage = Value
End Sub

Public Sub Main()
    Temperature = 20
    Dim Observed As Double = Temperature
End Sub

This specified example has not been executed with fresh v3. Assignment calls TemperatureWritten once; the initializer's read calls TemperatureRead once and obtains 20.

Signatures and behavior

For a variable of type T, the get hook is Function GetHook(ByRef Storage As T) As T and the set hook is Sub SetHook(ByRef Storage As T, ByVal Value As T). Parameter names do not matter. Each hook occurs at most once and its procedure name resolves in the declaration's lexical scope.

Reading calls the get hook and uses its return value. Assignment evaluates the right side once, then calls the set hook. Missing hooks use direct storage. A read/modify/write operation performs one hooked read followed by one hooked write. Initialization writes storage before hooks become active.

Backing storage and aliases

Only the privileged Storage parameter bypasses the hooks. Ordinary uses of Temperature inside either hook remain hooked and can recurse. The privileged parameter may be forwarded ByRef, but taking the hooked variable's address or passing it to an ordinary ByRef parameter is a compile-time error because that could bypass its hooks.

Placement, arrays and lifetime

Stored module, class and local variables can have hooks. A hook on an array variable observes the array value, not individual elements. Array-element hooks and first-class accessor references are reserved for a later version. Hooks retain ordinary storage ownership and thread rules; adding hooks does not synchronize shared mutable state.

Errors and optimization

Hooks are side-effecting. Optimization must preserve their number and order relative to observable operations. Recoverable hook failures follow the normal Err and explicit trapping rules. Reading the ordinary variable name inside its own hook can re-enter it; hooks do not create automatic recursion suppression.
