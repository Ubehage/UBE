VB6 migration

SpecifiedUBE 1.0 compatibility rulesImporter not released

UBE accepts core classic VB6 syntax, but it does not promise VB6 binary compatibility or every historical runtime behavior.

Importing source

Legacy .bas, .cls, .frm, and .ctl files may retain VERSION and Attribute VB_Name while being read as compatibility input. Saving a file as native UBE replaces that identity with a matching UBE SOURCE 1 header and Attribute UBE_Name.

Required changes

  • Give every variable an explicit type. Option Explicit Off is always an error.
  • Replace every DefBool, DefByte, DefCur, DefDate, DefDbl, DefInt, DefLng, DefObj, DefSng, DefStr, or DefVar directive with explicit As types. UBE recognizes these lines only to produce a targeted migration diagnostic.
  • Use Set for object-reference assignment, including an object stored in a Variant.
  • Replace assumptions about 32-bit pointers and handles with the appropriate target-safe type or platform declaration.
  • Audit conversions. Obvious conversions are supported, but invalid static conversions are compile-time errors and failed runtime conversions produce the documented neutral result and update Err.
  • Replace Option Compare Database; UBE diagnoses it as unsupported.

Behavior that deliberately differs

  • Integer arithmetic is checked instead of silently wrapping.
  • And and Or remain eager; use AndAlso and OrElse for short-circuit evaluation.
  • ReDim Preserve may resize any dimension but cannot change rank or element type.
  • As New creates the object when the declaration executes. It does not silently recreate an object after Set value = Nothing.
  • UBE has interfaces, but not class implementation inheritance.
  • Managed values may be collected later; cleanup of user-owned resources remains explicit.

Native project files

Native projects use .UBE manifests, .UBG project groups, and .UBR binary resource sidecars. Import tooling may read .vbp, .vbg, .frx, and .ctx, but the UBE compiler does not treat those as its native formats.

Recommended order

  1. Import without discarding the original project.
  2. Compile one module at a time and fix declarations and types.
  3. Separate Windows-specific calls into dedicated modules.
  4. Test conversions, overflow, error handlers, object cleanup, and form unloading.
  5. Move to a native .UBE manifest only after the source compiles as intended.
