Threads and CallNew

SpecifiedUBE 1.0Compiler support in progress

CallNew starts an existing Sub on a new UBE thread and returns its LongLong program thread identifier.

Example

Sub Worker(ByVal JobNumber As Long)
    Print JobNumber
End Sub

Sub Main()
    Dim WorkerId As LongLong
    WorkerId = CallNew Worker(7)
    ThreadWait(WorkerId)
End Sub

The target must be a directly visible, statically resolved Sub; a Function is not legal. Arguments are evaluated once from left to right and captured ByVal before the worker starts. Value data is copied and object identities are shared.

Identifiers and completion

Identifiers are nonnegative LongLong values, are not native handles, and are not reused during the process. Zero means creation failed and Err records the reason. A successful ThreadWait makes the worker's preceding changes visible.

Sharing data safely

Every thread may access state normally visible to its code. Scalar and reference reads do not tear, but competing unsynchronized operations have an unspecified order. Use SyncLock, atomics, thread events, semaphores, or message queues when order matters.

Stopping

Stopping is cooperative. ThreadRequestStop records a sticky request and wakes supported waits. The worker checks ThreadStopRequested() and returns through normal cleanup. UBE never forcibly terminates a thread.
