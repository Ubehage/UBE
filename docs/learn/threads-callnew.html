Threads and CallNew

SpecifiedUBE 1.0Limited native profile

CallNew starts an existing Sub or Function on a new UBE thread and returns its LongLong program thread identifier.

Current compiler profile

Native source workers are qualified for the admitted scalar and finite record/array profile, including ordinary ByVal copies and ByRef lifetimes. The examples on this page describe the full specified language. The current low-level library uses ThreadPrimitives.Wait(Id, TimeoutMilliseconds) with a required timeout. The global ThreadWait wrapper with an optional timeout, and the broader coordination library, are not qualified by those native worker tests.

Example

Sub Worker(ByVal JobNumber As Long)
    Print JobNumber
End Sub

Sub Main()
    Dim WorkerId As LongLong
    WorkerId = CallNew Worker(7)
    Call ThreadWait(WorkerId)
End Sub

The target and arguments use the same syntax and parameter rules as explicit Call. Subs and Functions are eligible; a Function result is discarded, while the CallNew expression returns the thread identifier. Zero-argument targets may omit parentheses. Arguments are evaluated once from left to right before the worker starts. Ordinary ByVal copies and ByRef aliases are preserved, with referenced storage and argument temporaries kept valid for the worker.

Identifiers and completion

Identifiers are nonnegative LongLong values, are not native handles, and are not reused during the process. Creation failure records Err and reports FAIL without a usable thread ID; the containing statement is skipped by default or transfers to its enabled handler. ThreadWait returns 1 for successful completion, or 0 for timeout or cancellation. If a fresh FAIL escapes the worker's entry procedure, the worker ends normally and a wait observing its completion reports fresh FAIL in the waiting thread, with the captured error number. The waiter uses its own error handler or default statement skipping. Repeated waits receive the same outcome. Normal return with an old Err is still successful. Observing either completion outcome makes the worker's preceding changes visible.

Sharing data safely

Every thread may access state normally visible to its code. Scalar and reference reads do not tear, but competing unsynchronized operations have an unspecified order. Use SyncLock, atomics, thread events, semaphores, or message queues when order matters.

Stopping

Stopping is cooperative. ThreadRequestStop records a sticky request and wakes supported waits. The worker checks ThreadStopRequested() and returns through normal cleanup. UBE never forcibly terminates a thread.
