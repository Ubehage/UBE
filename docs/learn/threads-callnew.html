Threads and CallNew

Partially implemented

CallNew starts a procedure on another UBE thread and returns its LongLong identifier.

Details

Arguments

Arguments are evaluated once before the worker starts. ByVal copies a value; ByRef shares the caller’s storage, which remains alive for the worker. A worker may be a Function, but its result is discarded. If creation fails, no usable identifier is returned.

Wait for completion

ThreadPrimitives.Wait(Id, Timeout) returns 1 on normal completion or 0 on timeout or a stop request to the waiting thread. Use -1 to wait indefinitely or 0 to poll. If failure escapes the worker, Wait reports it to the caller; an older stored Err alone does not mean the worker failed.

Coordinate safely

Wait makes completed worker updates visible. Do not use an unsynchronized shared variable as a completion signal. RequestStop asks a worker to stop; the worker checks StopRequested and returns normally. UBE never forcibly terminates it.

Note

The broader synchronization-object library is not yet implemented. Thread identifiers belong to UBE and are not operating-system handles.

Example

This example uses the current UBECore ThreadPrimitives module. The Wait timeout -1 requests an indefinite wait.

Private Sub DoubleValue(ByRef Value As Long)
    Value = Value * 2
End Sub

Public Function Main() As Long
    Dim Value As Long
    Dim WorkerId As LongLong
    Dim Completed As Long
    Value = 6
    WorkerId = CallNew DoubleValue(Value)
    Completed = ThreadPrimitives.Wait(WorkerId, -1)
    If Completed = 1 Then Main = Value
End Function

Result

After the worker completes, the program returns 12. The worker updates Value through its ByRef parameter; the wait makes that completed update visible to the caller.
