Memory, lifetimes, and resources

Partially implemented

UBE manages storage for strings and arrays. Your program closes its own files and other resources.

Details

Values stay independent

Assigning a String copies its value. Changing one variable later does not change the other. UBE keeps storage alive while it is needed, including when a worker refers to it; you do not free a String manually.

Collection

Leaving scope does not promise immediate collection. UBE collects automatically when memory is needed. Memory.CollectGarbage() requests a synchronous collection.

Resource cleanup

Close files, sockets and native handles on success and failure paths. Copying a resource token does not create a second owner. Follow the API’s recovery rules if close fails. Finish cleanup before Err.Raise, which immediately exits its procedure.

Note

Classes, finalizers and the full object lifecycle are not yet implemented.

Example

Public Function Main() As Long
    Dim Greeting As String
    Dim Copy As String
    Greeting = "Hello"
    Copy = Greeting
    Greeting = Greeting & ", UBE"
    If Copy = "Hello" Then Main = 1
End Function

Result

The program returns 1. Copy still contains Hello after Greeting receives a longer value.
