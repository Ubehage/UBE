Memory, lifetimes, and resources

SpecifiedUBE 1.0Compiler support in progress

UBE automatically manages memory used by strings, arrays, objects, variants, and recursive data. Your code remains responsible for files and other external resources.

Variable lifetime

A local variable leaves scope when its procedure or block ends. Its managed value becomes eligible for garbage collection when no live value can reach it. Cycles are collected, but collection need not happen immediately.

Global and module variables and initialized Static locals remain live until orderly shutdown. CollectGarbage() requests a synchronous collection and returns 1 if cleanup work occurred or 0 otherwise.

Class termination

An unreachable class receives Class_Terminate at most once before reclamation. Use it to release resources owned internally by the class, but do not depend on when collection happens. An object cannot restore itself to life from this event.

Close resources explicitly

Sub SaveResult()
    On Error GoTo Failed
    Open "result.txt" For Output As #1
    Print #1, "complete"
    Close #1
    Exit Sub
Failed:
    Close #1
End Sub

Close files, sockets, native handles, database connections, and similar resources on success, error, and cancellation paths. Garbage collection does not track them. The operating system closes remaining resources when the program ends, but that is not a substitute for timely cleanup.
