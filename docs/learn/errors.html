Errors and Err

SpecifiedUBE 1.0 specified

A recoverable runtime failure records information in the current thread's Err state and does not show an automatic dialog.

Handle an error

Sub ReadSettings()
    On Error GoTo Failed
    Open "settings.txt" For Input As #1
    Close #1
    Exit Sub
Failed:
    Print Err.Number
    Err.Clear
End Sub

On Error Resume Next continues after a failed statement. On Error GoTo 0 disables the procedure's active handler. Successful operations leave all earlier error information unchanged. Err holds the last error until Err.Clear or a valid Resume statement clears it, or a new error replaces it. A new error replaces all error information: omitted fields become empty or take their defined defaults, and never retain older values. Changing On Error mode or returning from a procedure does not itself clear Err.

When a failed operation needs a result, it returns the neutral value for its type. To distinguish a new failure from an old one, clear Err before the operation and check Err.Number afterward, use a fresh success/failure result when provided, or use an active handler.

On Error Resume Next retains the new error while continuing. The separate Resume, Resume Next, and Resume label statements leave an active handler and clear the recorded error as execution resumes.

If UBE can safely refuse a call because there is not enough stack space, the callee does not run, a function returns its neutral value, and Err.Number is 28. This is specified behavior; the fresh v3 native runtime does not yet implement it.
