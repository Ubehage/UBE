Errors and Err

Partially implemented

A failed operation records Err and, by default, skips the failed statement.

Details

Continue or handle the failure

On Error Resume Next selects the default skipping behavior. On Error GoTo label transfers control to a handler; On Error GoTo 0 restores skipping. Each procedure call starts with its own default mode rather than inheriting its caller’s handler.

Keep earlier work

Failure supplies no usable result. An unfinished assignment keeps its previous value, while a failed initializer leaves new storage at its neutral value. Earlier side effects and ByRef writes are not undone. By default, a runtime error in an If/ElseIf condition records Err and treats the condition as False, proceeding to the next ElseIf or to Else if no condition is True. Remaining operands in the failed condition are not evaluated. A failed loop condition leaves the loop. If evaluating a counted For initial value, limit or step fails, the whole loop is skipped without assigning the counter or evaluating later header expressions. An enabled handler receives control instead. Earlier effects remain completed. A failed For Each element is never assigned to the control variable; failure while preparing enumeration or an element ends the loop by default. By default, a failed SyncLock target or acquisition skips its complete block; an unacquired lock is never released.

Raise an error

Err.Raise immediately exits its procedure. Finish application resource cleanup first. In this example, the caller’s handler returns error number 5:

Private Function RequirePositive(ByVal Value As Long) As Long
    If Value <= 0 Then Err.Raise 5
    RequirePositive = Value
End Function

Public Function Main() As Long
    On Error GoTo Failed
    Main = RequirePositive(0)
    Exit Function
Failed:
    Main = Err.Number
    Err.Clear
End Function

Read Err carefully

Success does not clear Err, so an old error number does not prove that the latest operation failed. Err.Clear clears it; a new failure replaces the record. A failure inside an already active handler skips its statement without re-entering the handler.

Note

Additional Err members and Resume forms are not all implemented. See Resume for the wider contract.

Example

Public Function Main() As Long
    Dim Count As Long
    Dim TextValue As String
    TextValue = "not a number"
    Count = 25
    Count = TextValue
    Main = Count
End Function

Result

The program returns 25. Converting the text to Long fails, so the unfinished assignment is skipped. No zero is substituted for the failed conversion.
