Projects, modules, and files

Partially implemented

A .UBE project lists the source modules that make up your program.

Details

Native modules

A .bas file starts with UBE SOURCE 1 MODULE, then Attribute UBE_Name = "ModuleName". The name identifies the module. Add declarations and procedures below this header; reference examples omit it.

Project file

List each source in a .UBE file. Paths are relative to the project and stay inside its directory tree. The program needs exactly one parameterless Main: a Sub or a Function returning Long.

UBE-Project 1
Name = "Example"
Kind = "Exe"
Startup = "Main"
Source = "Main.bas"
Source = "Helpers.bas"

Across modules

Public procedures can be called from other modules; Private declarations stay in their module. Use a module qualifier to make the target clear. List required ordinary library source modules explicitly as Source entries.

Note

Empty named classes are supported in native .cls sources. Class members and lifecycle hooks, interfaces, forms, startup forms, general library references and resource packaging remain unsupported. Module lifecycle hooks are specified separately; see Project manifests.
