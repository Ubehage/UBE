Projects, modules, and files

Partially implementedUBE 1.0 specified; fresh v3 project syntax subset

A normal build reads a .UBE project manifest containing an ordered list of source and resource files.

Native source files

UBE SOURCE 1 MODULE
Attribute UBE_Name = "Main"

Sub Main()
End Sub

Use .bas for modules, .cls for classes, .frm for forms, and .ctl for controls. The header kind must match the extension. The UBE_Name attribute distinguishes native UBE source from imported VB6 source.

Project example

UBE-Project 1
Name = "Hello"
Kind = "Exe"
Startup = "Main"
Source = "src/Main.bas"
Source = "src/Messages.bas"

Paths are relative to the manifest and cannot escape its project tree. An executable has one parameterless Sub Main or Function Main() As Long. A library uses Kind = "Library", has no entry point, and exports only module procedures explicitly declared Public Export.

Initialization

A module's Module_Initialize, when defined, runs before Main. If initialization accesses another module that has not started, that module finishes initialization first. Circular references are allowed, but another module cannot read an unfinished module. Mutually waiting initializers may keep waiting until the program is stopped. The compiler warns about detectable circular initialization or termination references, and a future UBE IDE will show those warnings. Orderly shutdown calls defined Module_Terminate procedures in reverse initialization completion order.

The fresh v3 checks names and types in a bounded native MODULE and Exe/direct-UBECore subset. It does not yet produce a program. Classes, forms, controls, full libraries and resources remain unfinished. See current commands and limits.
