# Native result oracle coverage

This is a review inventory of proposed independent expectations, not native
execution evidence. A checked-in source fixture is marked “specified” only when
its hand-computed observable result is recorded; admission by the checker does
not prove the result. A category with one example is not exhaustive.

| Included behavior | Concrete or specified expectations | Remaining targeted cases |
| --- | --- | --- |
| Entry | `empty` Sub exit 0; `negative` Long -3; `recursion` neutral result; additional minimum and maximum Long projects specify full 32-bit process status. Additional projects have two-stage exact rejection checks for duplicate and invalid Main. | Execute signed extrema and altered-bit controls with full-width observation; verify build-path no-publication behavior for rejected entries. |
| Integer arithmetic | `fold`, `signed`, `overflow`, `recursion`, `conditions`, and `promotion` (Byte binary/unary promotion). Additional fixtures specify quotient/remainder signs, signed-minimum remainder for Integer/Long/LongLong, dynamic Long multiplication overflow, both Long subtraction overflow directions and adjacent in-range results, Long minimum divided by -1, negation of Long minimum and LongLong values above the 32-bit range. | Execute these fixtures and Err observer; cover further signed-width boundaries and multiplication extrema. |
| Bitwise and comparison | `bitwise` expects 53 for six Long bitwise operations; `comparisons` expects 59 for six signed comparisons. `additional/byte-bitwise` specifies Byte promotion for six bitwise operations. `additional/comparison-boundaries` specifies 36 for both outcomes of each operator on Byte and LongLong plus comparisons at signed Integer and Long extrema. `additional/signed-comparisons` specifies both outcomes of all six operators at Integer and Long extrema. | Execute these fixtures and wrong-width and unsigned-comparison controls. |
| Boolean and control | `order` checks skipped AndAlso; `eager` checks eager And/Or; `conditions` checks nonzero condition, nested While and ElseIf; `booleans` specifies Not, Xor/Eqv/Imp truth tables, equality and both evaluation paths of AndAlso/OrElse. Additional fixtures specify Boolean And/Or rows, inner-loop exit, single-line If branches and evaluation through a recoverable failure. | Execute the additional fixtures and implement their observer controls, including an independent Err observer. |
| Conversions and errors | `conversion`, `neutral`, `overflow`; additional observations in `ERROR-ORACLES.md` include initializer self-reference and subsequent use of storage after a failure, both orders of overflow and division by zero with the selected first-target error numbers, and an admitted integral narrowing boundary fixture. | Execute the matrix and remaining supported source/destination cases; observe actual Err identity/retention after each operation with independent controls. |
| Calls | `alias`, `optional`, `order`, `recursion`, `native-widths`; additional fixtures specify discarded results, shared ByRef aliases, nested named arguments, a recoverable error during argument evaluation, optional ByVal boundary defaults and `stack-call-effects` for a proposed refused call. | Execute the added fixtures and their controls, including the Err observer and a qualified stack guard. |
| Native values | `native` and `native-widths`; additional fixtures specify neutral locals for all three representations and Byte/Integer/Long extrema. `native-signed-boundaries` specifies both signed extrema through ByVal, result and ByRef; `native-many-arguments` specifies five distinct aggregate arguments. Target-level obligations are in `ABI-ORACLES.md`. | Execute neutral and extrema fixtures with wrong-value controls, verify multi-argument call boundaries, and measure actual target aggregate layout. |
| References and diagnostics | Direct UBECore references appear in the native fixtures; `startup` specifies dependency-first initialization, `additional/initializer-order` specifies declaration and module order, `initializer-events` supplies declaration/module-order cases without reading later modules' uninitialized storage, `reference-init-order` combines library declaration order with dependency-first initialization, and `reference-initializer-error` specifies a recoverable library initializer error followed by executable initialization. `FAILURE-ORACLES.md` defines failure experiments and three frontend rejection/defer controls with exact coordinates. | Execute initialization-order fixtures and controls; cover broader invalid/rejected/deferred projects, exact build-path diagnostics, no tool invocation, cleanup and preserved old artifact. |
| Determinism and resources | Contract specifies raw LLVM comparisons and work/resource categories. | Implement independent observer, fixed measurement bounds, real comparisons and injected failure/cancellation gates. |

The current fixture-admission script checks only that these project inputs are
accepted by the existing local checker with jobs 1 and 4. All expected native
values and the coverage gaps above still require future fresh-v3 execution.
