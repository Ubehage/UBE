# First grammar-consumer acceptance

Status: acceptance definition for the next item in `Roadmap.md`. This is not a
parser implementation, a chosen syntax-tree representation or a public phase
API. The current executable's qualified behavior remains source intake, raw
scanning and envelope recognition; successful intake reports checking unavailable.

## Authority and purpose

The primary authority is `../../lang-doc/language-spec.md`, especially sections
1–5 and 8, with phrase structure in `../../lang-doc/grammar/ube.ebnf`. Focused
normative contracts and the primary specification outrank conflicting expanded
wording. `SCANNER-CONTRACT.md` supplies raw lexical grouping, word roles and
original coordinates. `SOURCE-INPUT-CONTRACT.md` supplies exact immutable bytes.
The conditional directive grammar remains separately normative.

This consumer grows from the actual native MODULE source needed by fresh v3 and
portable UBECore. The complete language inventory is not its initial scope.
`tests/parser/` contains manually authored expectations, never expected answers
generated by an existing compiler. Its definition checker checks data consistency
and source spans; it does not parse source or prove those expectations correct.
Native comparison against the future UBE implementation is a separate gate.

## Bounded first scope

The first whole-source domain is native `UBE SOURCE 1 MODULE`, after qualified
envelope recognition, with no pending conditional compilation or designer data.
Kind/version/identity checks retain their existing envelope classifications.
Do not treat a legacy family marker as proof of its full file grammar.

Within that domain, the first consumer recognizes:

- Module options and inert module/member attributes; explicit variables and
  constants, canonical visibility/modifier positions, ordinary field-only Types
  and adopted native `Type Name As StorageType ... End Type` syntax.
- Sub, Function and Intrinsic declarations, typed names, parameter modifiers,
  optional defaults, array-rank syntax and result `As ElementType()` syntax.
  Array-bound declarations and qualified/intrinsic/fixed-String type spellings
  are syntax; rank, representability and type-policy validation remain separate.
- Local Dim/Static/Const, assignment forms, explicit and bare calls, single-line
  and block If/ElseIf/Else, While/Wend, With/End With, Exit, identifier labels,
  GoTo named labels and Return,
  statement separators, and the simple `Print expression` used by the compiler.
- Core expression phrase structure: primary/grouped expressions, postfix
  calls/indexing/member/bang access, operators, ordinary names/literals and the
  New/AddressOf/CallNew/TypeOf forms. Recognizing a phrase does not execute it,
  bind a call, validate object scope or create a thread.

The following remain outside this bounded consumer: CLASS/FORM/CONTROL bodies,
legacy/designer grammar and identity policy, Interface/Event/WithEvents/property
families, external Declare, hooks, Enum/legacy Def declarations, For/Do/Select/
SyncLock, numeric line-label forms, GoSub/computed branches, standalone End/Stop,
classic error/file/I/O
families beyond simple Print, Asm and Bytecode,
conditional evaluation and inactive-text recovery. Valid constructs outside the
scope receive a distinct deferred/unsupported disposition, never a fabricated
syntax error or a claim of complete checking. Deferred fixtures describe this
scope boundary; they do not validate the deferred construct.

The test entry labels `expression`, `statement` and `unit` are oracle contexts,
not a decision to expose those entry points in production. Expression fragments
must consume their complete logical input. A statement entry is one complete
statement line or structured statement; unit input includes its native header.
Source ending without a physical newline uses the scanner's zero-width logical
terminator. A declaration/procedure body may be empty where the grammar permits
it; a missing operand is not an empty expression.

## Required disambiguation

1. Preserve the scanner's longest valid lexical grouping and physical trivia.
   Do not retokenize `1&x` into `1`, `&`, `x`, join words across a continuation,
   erase meaningful spacing, or split an identifier to manufacture a keyword.
   Signs are separate tokens, not part of numeric AST identity.
2. At module scope a procedure header wins over a statement interpretation.
   At procedure scope `name = expression` is assignment; an equality may still
   appear on its right side. Reserved declaration names require brackets.
3. Expression calls and calls introduced by Call use parenthesized arguments.
   `Call F` and `Call F()` supply zero arguments. Bare `F x` uses the no-parens
   list; `F (x)` has one individually grouped argument. Bare `F(x)` must not be
   silently converted into the Call form. Retain individual argument parentheses
   for later ByRef rules. Empty slots survive; `()` is zero slots.
4. Named arguments retain their source order and `:=` grouping. Argument
   association, omitted required arguments, duplicate/unknown names, positional
   arguments after named ones and ParamArray restrictions require later binding
   checks; do not infer parameter contracts from punctuation alone.
5. A keyword after `.` or `!` remains a legal member name. Unbracketed reserved
   declarations are not legalized by that rule. Eligible ordinary library
   callees, including the explicitly specified `Mid$`, remain ordinary calls;
   their spelling never invokes a privileged builtin implementation. Preserve
   unambiguous use-site type characters separately from folded name identity.
6. Ambiguous adjacent use-site suffix/operator combinations are not silently
   resolved by dropping tokens. For example `x& + y` can expose an unresolved
   suffix-versus-concatenation question absent an additional disambiguation rule.
   Those combinations are explicitly deferred in this first scope. Established
   `a!b` member access and spaced power/concatenation retain their existing roles.
   This limitation does not ban use-site type characters from the language.
7. `Then` followed by a logical newline/comment selects block If. Otherwise
   Else binds to the closest unmatched single-line If. Preserve statement-start
   Rem behavior after Then/Else, guarded by member/parenthesis context. A colon
   inside arguments is not a statement separator; `:=` is never a colon split.
8. Recognize compound End terminators before treating standalone End as the
   deferred process-termination statement. The selected block
   grammar must not consume `End Function` as `End If`. The primary specification
   explicitly leaves incompatible procedure terminators to semantic validation;
   preserve both written kinds rather than rewriting or prematurely rejecting
   structurally admitted `Sub ... End Function`.
9. Leading-dot expressions occur only in With bodies and retain an innermost-
   With association. Me/New/AddressOf/TypeOf and CallNew remain syntax whose
   object/type/target legality is checked later. No name is resolved by the
   definition checker.

For the first consumer, an identifier followed by colon at the beginning of a
logical statement line is retained as a label, ahead of the otherwise possible
zero-argument-call/colon interpretation. This is an explicit consumer choice
under the owner's delegated syntax decisions, not a claim that EBNF alternatives
alone specified ordered choice. Numeric line-label ambiguity remains deferred;
it must not steal the literal from the structurally admitted `1 = 2` assignment.

Spacing follows explicit grammar requirements, including spacing1 around word
operators; the consumer must not globally skip trivia and accidentally widen
all those productions. Unclosed questions about expanded whitespace or adjacent
suffix ambiguity require focused witnesses and a written resolution before
widening this consumer. Existing source accepted by a permissive bootstrap tool
is not an independent language oracle.

## Expression grouping

Use the primary specification's actual precedence, even where another Basic
dialect differs. From lowest to highest: Imp; Eqv; Xor; Or/OrElse; And/AndAlso;
Not; comparisons; concatenation `&`; `+ -`; `* /`; integer division `\`; Mod;
unary `+ -`; power `^`; postfix/primary structure. Power is right-associative;
other binary operators are left-associative. Comparisons do not chain.

The hand-authored trees distinguish operand grouping, not evaluated results.
For example `a + b * c` groups Add(a, Multiply(b,c)); `a / b / c` groups
Divide(Divide(a,b),c); `a ^ b ^ c` groups Power(a,Power(b,c)); and a leading
negative sign binds outside power. `Not` binds outside comparison. `IsNot` and
`Is Not` share the logical IsNot node while retaining original source spelling.
No host arithmetic, constant folder or locale supplies an expected tree.

Typed suffix compatibility, overflow, constantness, invariant date/calendar
validation, call-versus-index binding and short-circuit execution are not proved
by shape recognition. Preserve date candidates only in their expression context;
file-number `#` and directive `#` need their own documented contexts.

## Syntax is not semantic acceptance

The EBNF intentionally admits forms that later checks reject. Examples include
nonassignable structural lvalues, a variable used in a constant expression,
omitted type annotations, incompatible procedure terminators, Option Explicit
Off and parameter ordering/default/type-policy violations. The `semanticChecks`
fixture metadata lists outstanding obligations; it is not a second checker and
does not claim every possible semantic error was enumerated.

Conversely, an executable body in an Intrinsic declaration, a field initializer
in field-only Type syntax, malformed parameter rank/bounds syntax or an absent
required phrase token is a structural issue in the chosen scope. Do not copy v2
diagnostic outcomes into this distinction: its supported subset and permissive
names differ from the frozen language.

## Conditional input and preserved source

Only selected conditional output reaches core parsing. Directives must retain
original logical coordinates and are not ordinary declarations/statements.
This definition does not evaluate symbols or settle malformed inactive quoting.
An inactive branch need only satisfy the primary specification's directive-
balancing lexical requirement. A future conditional consumer therefore cannot
require successful raw tokenization of the entire original file as a universal
precondition. Exact source bytes must remain available even when a provisional
   whole-file scan cannot produce a complete token array. This is a compatibility
constraint, not a newly chosen phase API or inactive-recovery algorithm.
The same applies to provisional envelope inspection of inactive reserved
attributes: success of an unselected whole-file metadata pass must not become
a universal prerequisite for later conditional selection.

## Logical witnesses and original positions

Fixture shapes describe observable grammar grouping, not storage. A node is
written `[Kind, witnessId, child, ...]`; `witnessId` identifies the full original
construct span. Operator kinds distinguish grouping; Name and Literal retain
raw spelling. All children are ordered, nonoverlapping siblings within their
parent. Coincident parent/child spans are legal. Header may contain name,
parameter-list and result witnesses. Procedure children are Header, any member
Attributes, Block and the written EndMarker; attributes are not body statements.

The vocabulary includes expression operators plus Module/Header/Attribute/
Option, RecordType/NativeType/Field, VariableDecl/ConstantDecl/Parameter/
Parameters/ResultType, Procedure/IntrinsicProcedure/Block/EndMarker, Assign/
LetAssign/SetAssign, CallStatement/CallKeyword, StatementList, IfLine/IfBlock/
ElseIf/Else/While/With/Exit/Label/Goto/Return/Print and LeadingMember. Its arities
are checked by the independent definition gate. This vocabulary freezes neither
production enum values nor an arena, node layout, object hierarchy or ABI.
Unused witnesses may anchor additional original source parts without demanding
an artificial tree node for every punctuation mark.

Each witness states its exact extent. Expression and statement witnesses usually
run from their first significant token to the last; Block witnesses can exclude
surrounding indentation, while unit/native-header composites may include required
line ends. Do not infer a universal trivia-trimming rule from the word "span".
The future native comparison must honor the explicit boundaries and retain the
entire original document, including source not owned by an individual witness.
These logical comparison views need not be the parser's storage layout.

Witness `text` selects an exact ordinal substring; `occurrence` is its zero-based
ordinal occurrence, including overlaps. With no `at`, the complete substring is
the span. `at: start` or `at: end` instead selects a zero-width boundary of that
nonempty anchor, useful for omitted argument slots. `at: eof` requires empty
text and selects original EOF. Boundary anchor text is not invented span content.
Coordinates are the existing zero-based UTF-8 byte/scalar and one-based scalar
line/column system: initial BOM is three bytes/zero scalars, CRLF two scalars/one
line, supplementary characters one scalar, tabs one column. Optional explicit
numeric anchors independently cross-check selected positions.

## Diagnostics, resources and publication

Reject fixtures give the first required diagnostic, anchored at the offending
token or zero-width original EOF. The domain labels are ExpectedExpression,
ExpectedToken, ExpectedIdentifier, UnexpectedToken, InvalidCallSyntax,
UnterminatedBlock and UnexpectedTerminator; they are not a numeric diagnostic
ABI. Lexical/envelope errors retain their own earlier qualified classifications.
Resource/domain/admission failure must remain distinct from malformed syntax.

The initial recovery contract is stop after the first required diagnostic.
Every parser loop must consume input or stop; a failed alternative cannot retry
the same suffix indefinitely. No partially successful syntax result is published.
Multiple-error recovery can be proposed later with independently specified
ordering and synchronization witnesses; it is not required to finish this slice.

The source limit remains 16777216 bytes and token limit 1048576. Before native
implementation, require explicit caller budgets for output records, pending
nesting/work and diagnostics. Initial boundary probes use 256 open groups/blocks
or pending unary/right-associative operands and one first-error diagnostic.
These are resource probes, not language rank limits or mandatory AST depth:
long flat left-associative chains must not create unbounded host recursion.
No source-controlled recursion may overflow the host stack. Exact budget counting
and lower/at/above-limit fixtures must be recorded with the representation probe
before a production implementation is chosen.

One caller owns pending parser state and output; input documents/tokens are
borrowed immutable views. Share only immutable inputs/data across independent
calls. Keep sources alive for every returned span. Initialize complete failure
fallbacks before managed calls; use fresh status, never stale Err. Failure at
admission, growth, preparation or final publication preserves complete old output
and all source ownership. Clean roots and temporary storage on every early exit.
No external resource, worker pool, generic collection or String implementation is
justified merely by this definition.

## Required implementation evidence and exact next action

After this definition passes, run focused representation/algorithm probes against
the independent grouping witnesses and native failure/cost requirements before
choosing production layouts or parser strategy. Do not import an archived parser
or select one merely because it self-hosts. Reuse existing typed arrays/records,
source snapshots and ordinary library helpers where the probes justify them.

Qualification of an actual consumer will require both source-built bootstrap
stages with intact UBE sources and real UBECore Reference, exact node/diagnostic/
source-span comparisons, unchanged inputs and old-output retention, resource and
root/allocator failures, zero residual roots/live payload, deterministic private
worker results and byte-identical raw LLVM. Test both accepted and deliberately
corrupted comparison controls. No successful fragment proves a complete program.

Measure actual token inspections, grammar transitions, source/payload copies,
allocations, capacity/zero-initialization requests, temporary workspace and roots,
retained source/old output and cleanup. Separate fragment parsing, envelope work,
literal/name cooking and test-harness overhead. Require zero source-payload copies
and no whole-array/subtree copy per append; measure flat and deeply nested inputs
at increasing sizes. Demand linear work in input plus emitted result for this
bounded grammar, excluding explicitly measured lookup/cooking work. Set concrete
representation-specific copy/work constants before production coding, not after
observing an expensive implementation. Definition counts and wall time cannot
substitute for these native measurements.
