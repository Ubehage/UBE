# Semantic storage and lookup probes

Status: preset probe contract for the approved First semantic checking goal.
Production semantic storage is not selected by this document. Execute only
after the retained declaration-detail consumer is qualified. The source-built
bootstrap stages, retained input owners and tested library boundaries remain
the prerequisites; no archived implementation is an algorithm oracle.

## Questions and candidate boundary

1. Prove the concrete Boolean/Byte/Integer/Long/LongLong operations, records,
   arrays, reference sharing and checked access that a candidate actually uses.
   In particular, thread-identity LongLong support does not establish general
   signed-64 arithmetic or every boundary needed by constant evaluation.
2. Measure privately constructed scalar-record arenas, explicit traversal work,
   complete-result publication and immutable cross-thread access. Reuse the
   qualified syntax arena pattern where useful, without assuming its measured
   constants automatically qualify a different semantic payload.
3. Compare sorted indexes with binary lookup against bounded open-address indexes
   over caller-supplied byte keys. A linear reference is an independent small
   control, not an acceptable production whole-module scan per name use.
4. Prove canonical name production once per declaration/use: existing Unicode
   simple folding, bracket unescaping and parser-selected suffix separation,
   while retaining original source identity/spans. Identifier grammar and scope
   policy remain compiler-owned; generic byte-key algorithms belong in UBECore.

The candidates use only repository-owned UBE and the adopted bounded substrate.
Their record/array layouts and exact entry signatures are test-only until
measured. Freeze a chosen reusable library contract and callable names before
production implementation. No general callbacks, generic language syntax,
public phase API, scheduler or implicit builtin lookup is introduced.

## Independent data and expected results

Preset key counts: 0, 1, 8, 64, 1024 and 16384; include increasing and reversed
input order, interleaved duplicate keys, empty keys, embedded zero bytes and
unequal long common prefixes. Query every existing key, both sides of range
boundaries, and independently authored misses. Values are stable caller indexes,
not insertion/completion-dependent identities. Duplicate lookup returns the
complete equal-key range/group in stable input order; visibility/ambiguity and
which group is relevant are compiler policy, not library tie-breakers.

The Unicode/name cohort includes K versus Kelvin sign, distinct composed versus
decomposed spellings, bracketed escaped closing brackets, declaration/use suffix
agreement and supplementary characters. Expected canonical bytes and associations
must be hand-authored from the pinned Unicode rules, never generated by the
candidate or an archived compiler. Source snapshots remain byte-identical.

The numeric prerequisite cohort independently checks zero, signed minima/maxima
and adjacent failures for every selected width, two-limb/magnitude handling when
needed for a signed minimum, promotion, checked add/subtract/multiply/divide/Mod,
and division truncation/remainder sign. Observe actual result and failure status;
a bootstrap compile is insufficient. Constant error and ordinary runtime failure
remain distinct requirements. Do not inherit host conversions or undefined
overflow. The owner-confirmed 40000 - 10000 and destination-context LongLong
examples are mandatory cross-checks, including explicit-suffix constraints.

## Costs fixed before measurement

Count executed key-byte reads, comparisons/probes, record/slot writes, allocations,
copied bytes, requested/zeroed capacities, live and peak roots, physical array/GC
headers and retained payload. Count traversals, not formulas manufactured from N.
Separate canonical key construction, index construction, lookup and publication;
test setup/expected-answer work stays outside observations.

- Zero copies of original source payload or complete declaration catalogs into
  a body worker. Canonical key bytes are derived data, measured separately.
- Scalar arenas grow geometrically; payload copied by growth is at most twice
  peak live payload plus the initial eight-record allowance. Final trim and
  whole-result publication each copy at most one complete logical payload.
  No per-insert whole-table copy or per-query complete index copy.
- For a sorted candidate, allow at most two N-entry scratch/index arrays and
  one stable key-record arena, apart from the single owned/borrowed key-byte
  store and retained old result. The test candidate uses stable bottom-up merge
  sorting with run widths 1, 2, 4, ...; equal keys select the left entry. For N
  entries there are at most ceil(log2(N)) passes, at most N comparisons and N
  output-entry writes per pass, plus at most N writes to initialize stable
  caller indexes and N final placement writes when the last pass used scratch.
  Thus total ordering writes are at most N*(ceil(log2(N))+2). Release scratch
  before complete-result publication, keeping at most two N-entry arrays live
  apart from the retained old result. With the existing copying array-result
  publication, unreclaimed scratch can still occupy physical collector storage:
  preset at most three N-entry allocated payloads per complete build attempt,
  plus pending/published wrapper payloads and their measured physical headers.
  Report reachable bytes separately from physically retained bytes; dropping
  a reference is not proof of immediate reclamation. Prove zero retained
  temporary payload after roots are released and collection runs. No recursive
  sorting stack or per-merge allocation. Compare
  lengths before reading past either key. Each comparison reads at most twice
  the smaller key length in payload bytes; an equal prefix is ordered by length.
  Measure actual reads/comparisons/writes against these bounds, including N=0/1.
- For a hash candidate, preset a maximum load factor of one half and at most
  four N-sized bucket slots after geometric rounding, plus key/entry storage.
  Explicitly measure adversarial collisions. Reject an unbounded quadratic
  strategy or define and test a controlled caller-work limit before adoption;
  expected average O(1) is not a worst-case safety proof.
  The test candidate stops construction after 32*N+32 executed bucket probes
  and returns a distinct caller-work-limit status with the old result intact.
  Lookup stops after 32 executed bucket probes per boundary query with the
  same explicit status. Include a deliberately colliding test hash as a control;
  failure to complete that cohort disqualifies an unconditional lookup claim.
  This limit is a probe policy, not an adopted compiler or public-library limit.
- Binary lookup must use at most ceil(log2(N+1))+1 key comparisons per lower/
  upper boundary, plus the reported equal-key result range. Measure byte work
  for long-prefix names separately rather than hiding it in comparison count.

Use the same complete corpus and observation boundaries through both current
source-built stages. Report raw LLVM identity, requested versus physically
written/retained memory, complete result hashes and actual observations. Select
from evidence about the real bounded compiler need, not the easiest microcase.

The diagnostic test candidates now make the following serial-operation bounds
concrete for the eventual maintained acceptance run. They follow from exact
known-count allocation and the current bounded runtime's local copy workspace;
the earlier functional-only run establishes none of these physical bounds.
Let A and G be the independently observed array and collector header sizes,
P the native wrapper size, and B the hash bucket count. Inputs/old results and
their headers are reported separately, outside these additional-byte bounds.

- Sorted construction: at most eight actual allocator calls, at most
  12*N+2*P+5*(A+G)+8 requested bytes, and at most 12*N+2*P+5*A additional
  collector payload at observed allocation/publication boundaries. The 8-byte
  allowance is the existing array-slot publication workspace. At most
  4*N+12 actual payload bytes copy during complete publication; no other
  payload copies and no key-byte copies. Wrapper scalar metadata is 12 bytes.
- Hash construction: at most twelve actual allocator calls, at most
  8*(B+2*N)+2*P+8*(A+G)+8 requested bytes and
  8*(B+2*N)+2*P+8*A additional collector payload. Successful publication
  copies exactly 4*(B+2*N)+12 payload bytes. Controlled work exhaustion
  publishes nothing and copies zero payload bytes.
- Each query allocates and copies nothing. Serial build/query peak roots
  exceed their observed baseline by at most 512, independently of N.
  Compare actual byte-read/write/comparison events with UBE metrics, not just
  formulas printed by the candidate. Every successful comparison reads at most
  twice the smaller key length; hash byte work additionally includes exactly
  the input/query spans actually hashed. The deliberate collision hash reads
  no payload while hashing, but its equality checks still count all reads.

Count and report calloc-zeroed bytes separately from requested allocator bytes
and logical capacity. Do not label requested bytes physical writes. Exercise
negative controls against copied bytes, counters, allocation and retained-memory
bounds. The later maintained run must apply the frozen bounds; a diagnostic run
started before this concrete observer ledger is not final acceptance.

The ordinary-UBE decimal/numeric candidate adds no numeric representation or
literal syntax policy. Its concrete observer bounds for the maintained run are:
zero allocation and zero payload copying in decoding, scalar arithmetic and
comparison; at most 16 additional managed roots for a byte-span decode and
zero additional managed roots for scalar arithmetic/comparison. A successful
decode reads exactly the supplied digit count once; a failure reads no more
than the validated span. Count actual checked-machine-helper calls: at most
8*executed-byte-reads+8 per decode, eight per scalar evaluation and one per
comparison. These bounds include the bootstrap's explicit checked loop-counter
arithmetic. Probe scalar work while the actual root registry is completely full.
All logical domain/format/range/division outcomes preserve the old output and
Err, including preexisting Err 7; managed admission returns its distinct fresh
failure status and preserves the old output. Negative decimal accumulation must
accept signed minima without constructing an unrepresentable positive value.

## Failure, lifetime and sharing

Exercise actual allocation/root denial at admission, growth, sort/hash scratch,
key preparation, trim and publication. Retain a different complete old result
and its source/key owners throughout failure, then prove later recovery. Fresh
status never comes from stale Err. Test invalid and zero/below/exact/above
resource budgets, overflow-safe capacity arithmetic and explicit-stack depth.
Every failed attempt must release temporary roots/payload and external handles.

Four actual UBE workers must share one immutable finished index and retained
input owner, use private query/traversal/results, and return identical complete
answers in repeated and reversed completion orders. Capture only bounded IDs
and owner references; count actual capture copies. Test separate simultaneous
contexts and an intentionally invalid unowned borrow as a negative control.
Use existing generic Threads facilities for component proofs; the production
compiler's one-budget orchestration remains a separate integration obligation.

## Exit and implementation sequence

Publish exact candidate inputs/tools/commands/results, independent oracle and
observer corruption controls, actual failure sweeps and cost rows. A failing
bootstrap prerequisite requires a focused synthetic reproduction before repair;
do not redesign shared mechanisms from speculation. Unmeasured or failed
candidates cannot become production by renaming their status.

After selection, document the lasting compiler-owned result/ownership design
and any newly needed UBECore facility under its contributor rules. Independently
author complete semantic streams for representative projects as well as the
existing targeted observations. Then implement the bounded checker against the
qualified declaration detail, preserved source owners and single worker budget.
No probe or fixed point establishes full-language/backend acceptance.
